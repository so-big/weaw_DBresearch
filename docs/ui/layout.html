DBresearch layout and upload

PC and tablet use top tabs. Phones use a bottom bar with a large search button in the middle, because people on phones mostly search and download. Upload is one button that opens a window for several files at once, and checking the auto-filled details can wait. Both mocks below work: try the tabs, the upload button, dragging PDFs onto the PC mock, and the phone's search button.

Phone (narrower than 768px): bottom bar, raised search button in the middle. Upload stays reachable from the header, but it isn't in the bar.

Upload flow

Upload button, or drop files on the page→ Window: drop zone + choose files→ Each file shows its own progress and result→ Review now or Review later
Many files at once

Files go up two at a time, so a 40-file batch doesn't freeze a slow connection. Each row shows its own progress, then one of: uploaded, already in the system (with a link to the existing document), or not a PDF.

Close it anytime

Closing the window doesn't stop the upload. A small progress pill stays in the header, and clicking it reopens the window.

Review now or later

Every new document waits in the รอตรวจสอบ tab with a count badge. It's searchable straight away, and its details can be edited any time. That fits moving the old archive into the system in bulk.

One rule from the backend

A document is marked ready only once its type and funding type are set. "Review later" leaves it in รอตรวจสอบ until then; it is never blocked or lost.

Motion rules: smooth on low-end phones

Animate only transform and opacity

The phone's graphics chip handles these without recomputing the page layout. Never animate width, height, top/left or shadows. The tab underline above slides with a transform.

Short and quick
  • 150ms for hovers and presses
  • 220ms for windows, sheets and switching tabs
  • One ease-out curve everywhere
No jumping content

Space for lists, images and badges is reserved before data arrives. Grey placeholder rows show where results will appear, so the page never jumps when they load.

Feels instant

Show the result first and confirm in the background: a new file row appears the moment it's dropped. Search updates as you type, waiting 250ms after the last keystroke.

Things we skip
  • Blurred see-through backgrounds (slow on cheap phones)
  • Big scroll-triggered effects
  • Page-wide spinners
Respect the setting

When the phone or PC is set to reduce motion, everything switches instantly. Page changes use the browser's View Transitions where available, and simply switch where not.
